# UI Spec 001：HomePi Monitor Linux Console 产品界面

> 文档 ID：UI-001  
> 版本：0.3
> 日期：2026-08-11
> 状态：已认证
> 目标终端：横屏 60×20，Linux console 彩色主题 + 7-bit ASCII 降级，480×320，Fixed 8x16 字体
> 运行时验证：Pi 3 B+ 实机 `stty size < /dev/tty1` 返回 `20 60`，UI-001 推断已落地

## 1. 设计目标

本界面用于 Raspberry Pi 3 B+ 的无触摸、无键盘 Kiosk。设计优先级依次为：五秒内读懂、状态不失真、视觉层级清晰、断网仍可读、低频重绘、最低字符集兼容。

Phase 1 只展示一台主力开发电脑，不出现节点选择器、按键提示、触摸提示、滚动条或设置入口。

## 2. 视觉语言

- 目标 DietPi 默认使用受控的 Linux console SGR 色彩与字库内单宽字符；纯 ASCII 是强制降级契约，不再是默认视觉上限。
- 页面结构固定为：状态头、主要数据区、设备状态、同步页脚。
- 数字右侧对齐；百分比、余额和时间采用等宽数字。
- 每个状态同时使用短文本，颜色只作增强，不能作为唯一表达。
- 不使用动画、spinner、闪烁、渐变或大面积反色。
- 页面使用亮青色框架、青色标题、白色主值、绿色正常、黄色告警、红色严重、洋红 Kiosk 标识；避免对无语义的单个字符逐字着色。

### 2.1 实机能力与字符集

2026-08-11 对当前 DietPi 实机只读探测得到：`TERM=linux`、`tput -T linux colors=8`、
键盘处于 Unicode UTF-8 模式、`LANG=C.UTF-8`、console-setup 为 `Fixed 8x16`，TTY 为 60×20。
Linux console 的亮色通过粗体 SGR 组合表达，不假设 256 色。

`rich` 主题仅使用以下附加字符，均按一个终端单元计算：

| 用途 | 字符 | ASCII 降级 |
|---|---|---|
| 外框四角 | `┌ ┐ └ ┘` | `+` |
| 分隔线接点 | `├ ┤` | `+` |
| 横线/竖线 | `─ │` | `- \|` |
| 进度已剩余/已消耗 | `█ ░` | `# -` |

渲染器生成的 ANSI 序列只允许 SGR 前景色/粗体与行尾 reset；远端、Provider 或配置文本仍先经过
7-bit ASCII 清洗，任何输入都不能注入控制序列。`HOMEPI_DISPLAY_STYLE=ascii` 必须输出原有、无 ANSI、
无 Unicode 的 golden screen；未知样式必须拒绝启动，不能静默选择不确定主题。

## 3. 60×20 安全网格

- 最大宽度：60 个终端单元，包含左右边框。
- 最大高度：20 行，包含上下边框。
- 外边框固定为 60 列；所有内容行内宽为 58 列。
- Provider 名最多 12 个 ASCII 字符；超长名称截断为前 11 字符加 `~`。
- Phase 1 不滚动。空间不足时依次隐藏次要说明、周窗口、重置时间；不得隐藏主值和状态。
- 运行时 TTY 尺寸不是 60×20 时，由 Layout Engine 选择降级布局；不得把内容写出终端边界。
  Pi 3 B+ 实机当前尺寸精确为 60×20（详见第 4 节 R012 与 IMPL-001 第 2.2 节），因此
  任何与 60×20 不一致的渲染都属于回归。

列宽参考：

```text
0         1         2         3         4         5
123456789012345678901234567890123456789012345678901234567890
```

## 4. Phase 1：Coding Overview

正常状态的 ASCII 降级首屏如下。进度条表达“剩余”，ASCII 模式中 `#` 为剩余额度、`-` 为已消耗额度；rich 模式用亮青色 `█` 表达剩余、亮黄色 `░` 表达已消耗，列位置完全相同。进度配色固定，不随卡片状态改变；卡片状态仍由右侧文字徽标及其绿/黄/红/洋红色表达。

### 4.0 固定列位置

内容区宽 58 单元，下列偏移为 0 基下标，由 `internal/ui/render.go` 的列常量固化：

| 元素 | 偏移 | 对齐 |
|---|---:|---|
| 节点别名 | 9 | 左，最多 12 字符 |
| 页面名 | 26 | 左 |
| 连接状态 | 39 | 左 |
| 时钟 | 50 | 左 |
| Provider 名 | 1 | 左，最多 12 字符 |
| 进度条 | 13 | 固定 18 单元（`[` + 16 + `]`） |
| 重置列 | 46 | 左 |
| 状态徽标 | 52 | 右 |
| 区块告警计数 | 54 | 右 |
| 余额金额 | 28 | 右 |

| 页脚版本 | 39 | 左 |

原始手绘样图中正常页脚右列在第 24 格、空状态页脚右列在第 25 格。实现统一为 24，
使所有状态下的页脚在同一列对齐。

### 4.1 信息层级

1. 顶栏：产品、唯一 node 别名、页面、连接状态、本地时间。
2. Coding Plans：Codex、MiniMax、Kimi Code，固定按用户配置顺序展示。
3. API Balance：DeepSeek API、Kimi API；余额不得伪装成 Token 剩余百分比。
4. Pi 状态：温度、CPU、内存、LAN。
5. 页脚：告警数量、同步新鲜度、数据来源、Kiosk 状态和版本。

### 4.2 进度条规则

- 固定 16 格，按剩余百分比四舍五入到最近格。
- rich 模式中括号和 `█` 使用亮青色，`░` 使用亮黄色；让剩余与已消耗快速分区，同时避免把整条进度误读为告警状态。
- 上游没有 limit 时不显示进度条，改用 `VALUE --` 或金额主值。
- `estimated`/`manual` 值在主值后追加 `EST`，不能显示为精确 `OK`。
- 剩余值和使用值不得在同一行混用；默认统一显示 `LEFT`。

### 4.3 时间格式的两种取整

- 「距今多久」向下取整：观察于 119 秒前显示 `1M AGO`，不显示 `2M AGO`，避免高估陈旧度。
- 「还有多久重置」四舍五入到最近单位：距重置 1 小时 59 分显示 `RESET 2H`。
  若同样向下取整，整个窗口内几乎都会显示 `RESET 1H`，持续低估等待时间。

## 5. Phase 1 状态变体

### 5.1 node 离线

```text
+----------------------------------------------------------+
| HOMEPI  DEV-MAC          CODING       OFFLINE    14:44   |
+----------------------------------------------------------+
| CODING PLANS                                   1 WARN    |
| Codex       [#######---------] 42% LEFT      RESET 2H    |
|   5H 42% LEFT | WEEK 67% LEFT                 STALE      |
| MiniMax     [###########-----] 68% LEFT      RESET 2H    |
|   5H 68% LEFT                                 STALE      |
| Kimi Code   [######----------] 35% LEFT      RESET 4H    |
|   5H 35% LEFT | WEEK 51% LEFT                 STALE      |
|                                                          |
| API BALANCE                                              |
| DeepSeek API       CNY 8.20                   STALE      |
| Kimi API          CNY 49.58                   STALE      |
+----------------------------------------------------------+
| PI 52C      CPU 3%      MEM 18%      LAN         OK      |
+----------------------------------------------------------+
| DATA STALE 12M         LAST SYNC 14:32       RETRYING    |
| SOURCE DEV-MAC      KIOSK LOCKED      V0.1.0             |
+----------------------------------------------------------+
```

已有主值继续显示，但每个受影响连接器的状态改为 `STALE`。页面不清空，不显示虚假的零值。

顶栏优先级为 `WAIT` > `OFFLINE` > `CRIT` > `LIVE`。**`OFFLINE` 高于 `CRIT`**：链路断开时
屏幕上全部是最近成功值，按第 7 节「先检查新鲜度再检查数值」的原则，顶栏不得断言一个无法
确认的实时严重状态。卡片级 `CRIT` 徽标与页脚告警计数仍然显示，信息不丢失。

+----------------------------------------------------------+
| HOMEPI  DEV-MAC          CODING       LIVE       14:32   |
+----------------------------------------------------------+
| CODING PLANS                                   2 WARN    |
| Codex       [----------------] -- LEFT         AUTH      |
|   ACTION: RE-AUTH WITH OFFICIAL CLI ON DEV-MAC           |
| MiniMax     [###########-----] 68% LEFT      RESET 2H    |
|   5H 68% LEFT                                    OK      |
| Kimi Code   [######----------] 35% LEFT      RESET 4H    |
|   5H 35% LEFT | WEEK 51% LEFT                  WARN      |
|                                                          |
| API BALANCE                                              |
| DeepSeek API       CNY 8.20                    WARN      |
| Kimi API          CNY 49.58                      OK      |
+----------------------------------------------------------+
| PI 52C      CPU 3%      MEM 18%      LAN         OK      |
+----------------------------------------------------------+
| 2 WARNINGS             SYNCED 38S AGO                    |
| SOURCE DEV-MAC      KIOSK LOCKED      V0.1.0             |

右侧，详情行让给必须执行的动作。

### 5.4 严重告警

- 顶栏连接状态位置显示 `CRIT`，**前提是链路仍然在线**；离线时顶栏显示 `OFFLINE`，
  见 5.1。
- 告警卡移动到数据区第一项，但固定 Provider 顺序在告警解除后恢复。
- 目标行使用 `CRIT` 文本；若有颜色则只将该行和告警计数设为红色。
- 严重告警不闪烁，避免 SPI 屏持续重绘。

## 7. Phase 3：远程显示覆盖

远程消息占用数据区顶部三行，并保留来源、严重度和自动恢复倒计时：

```text
+----------------------------------------------------------+
| REMOTE NOTICE                 HIGH     14:40             |
| HOMELAB MAINTENANCE STARTS IN 10 MINUTES                 |
| SOURCE DEV-MAC                RETURN IN 25S              |
+----------------------------------------------------------+
```

消息文本必须清除控制字符并截断到可见区域；不解析 ANSI、Markdown、URL 或命令。到期后恢复抢占前页面。

## 8. 状态与颜色映射

| 文本 | 可选颜色 | 含义 |
|---|---|---|
| `OK` / `LIVE` | 亮绿色 | 当前值有效且在新鲜度窗口内 |
| `WARN` | 亮黄色 | 配额、余额或资源接近阈值 |
| `CRIT` / `DOWN` / `ERROR` | 亮红色 | 严重阈值、目标离线或采集错误 |
| `STALE` / `OFFLINE` | 黄色 | 显示的是最近成功值 |
| `AUTH` | 亮洋红 | 官方 CLI 登录态需用户在远端续期 |
| `N/A` | 白色 | 上游不支持或兼容接口不可用 |
| `WAIT` / `DELAY` | 亮青色 | 等待第一份快照或按设计延迟 |

## 9. 文本与数值格式

- 时间：`14:32`；距今：`38S AGO`、`12M AGO`、`2H AGO`。
- 重置：`RESET 2H`；滚动恢复但无准确时间：`ROLLING`。
- 金额：`CNY 49.58` 或 `USD 12.30`，币种永不省略。
- 百分比：整数显示；低于 1% 时显示 `<1%`，未知显示 `--`。
- 温度：`52C`；CPU/内存/磁盘为整数百分比。
- Node 别名推荐不超过 12 字符；Provider 显示名推荐不超过 12 字符。
- 所有用户可配置文本必须清除控制字符和不可打印字符。

## 10. 重绘策略

- 数据变化时只更新状态模型，由终端渲染器输出一帧完整的确定性画面。
- 无数据变化时仅在分钟变化、新鲜度等级变化或轮播切页时重绘。
- 不使用 spinner、进度动画或闪烁光标。
- 光标隐藏；应用退出或崩溃时由恢复逻辑还原终端状态。

## 11. 验收标准

- 正常 Phase 1 首屏剥离 ANSI 后严格为 60×20；rich 模式只使用本规格列出的单宽字符，ASCII 模式只使用 7-bit ASCII。
- 五类 Phase 1 指标、唯一 node、新鲜度、Pi 健康和版本无需滚动即可看到。
- 无颜色、无 Unicode、stdin 关闭时通过 ASCII 模式保持信息结构和状态语义完整。
- `LIVE`、`OFFLINE`、`AUTH`、`STALE`、`CRIT` 和无快照状态可仅凭文本区分。
- 任何 Provider 名、数值、远程消息或错误文本都不能写出 60 列边界。
- 页面不出现键盘、触摸、退出或本地设置提示。
