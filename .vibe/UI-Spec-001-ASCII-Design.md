# UI Spec 001：HomePi Monitor Linux Console 产品界面

> 文档 ID：UI-001  
> 版本：0.9
> 日期：2026-10-10
> 状态：待本轮验收
> 目标终端：横屏 60×20，Linux console 彩色主题 + 7-bit ASCII 降级，480×320，Fixed 8x16 字体
> 运行时验证：Pi 3 B+ 实机 `stty size < /dev/tty1` 返回 `20 60`，UI-001 推断已落地

## 1. 设计目标

本界面用于 Raspberry Pi 3 B+ 的无触摸、无键盘 Kiosk。设计优先级依次为：五秒内读懂、状态不失真、视觉层级清晰、断网仍可读、低频重绘、最低字符集兼容。

Phase 1 只展示一台主力开发电脑，不出现节点选择器、按键提示、触摸提示、滚动条或设置入口。

## 2. 视觉语言

- 目标 DietPi 默认使用受控的 Linux console SGR 色彩与字库内单宽字符；纯 ASCII 是强制降级契约，不再是默认视觉上限。
- 页面结构固定为：状态头、主要数据区、设备状态、同步页脚。
- 数字右侧对齐；百分比、余额和时间采用等宽数字。
- 每个状态同时使用短文本，颜色只作增强，不能作为唯一表达。
- 不使用动画、spinner、闪烁、渐变或大面积反色。
- 页面使用亮青色框架、青色标题、白色主值、绿色正常、黄色告警、红色严重、洋红 Kiosk 标识；避免对无语义的单个字符逐字着色。

### 2.1 实机能力与字符集

2026-08-11 对当前 DietPi 实机只读探测得到：`TERM=linux`、`tput -T linux colors=8`、
键盘处于 Unicode UTF-8 模式、`LANG=C.UTF-8`、console-setup 为 `Fixed 8x16`，TTY 为 60×20。
Linux console 的亮色通过粗体 SGR 组合表达，不假设 256 色。

`rich` 主题仅使用以下附加字符，均按一个终端单元计算：

| 用途 | 字符 | ASCII 降级 |
|---|---|---|
| 外框四角 | `┌ ┐ └ ┘` | `+` |
| 分隔线接点 | `├ ┤` | `+` |
| 横线/竖线 | `─ │` | `- \|` |
| 进度已剩余/已消耗 | `█ ░` | `# -` |

渲染器生成的 ANSI 序列只允许 SGR 前景色/粗体与行尾 reset；远端、Provider 或配置文本仍先经过
7-bit ASCII 清洗，任何输入都不能注入控制序列。`HOMEPI_DISPLAY_STYLE=ascii` 必须输出原有、无 ANSI、
无 Unicode 的 golden screen；未知样式必须拒绝启动，不能静默选择不确定主题。

## 3. 60×20 安全网格

- 最大宽度：60 个终端单元，包含左右边框。
- 最大高度：20 行，包含上下边框。
- 外边框固定为 60 列；所有内容行内宽为 58 列。
- Provider 名最多 12 个 ASCII 字符；超长名称截断为前 11 字符加 `~`。
- Phase 1 不滚动。空间不足时依次隐藏次要说明、周窗口、重置时间；不得隐藏主值和状态。
- Phase 1 首屏中，仅有 weekly 窗口的卡片也必须使用标准两行布局：第一行保留主值和完整的 `RESET` 文案，第二行显示 `5H --` 占位符并在共享状态列显示状态徽标；`5H --` 只表示窗口不存在，不得让状态徽标与占位符或 `RESET` 文案粘连、重叠或被网格截断。轮播 `CODING` 页的 weekly-only 卡片使用第 6.1 节的三行布局，`5H --` 占位符在详情行。
- 运行时 TTY 尺寸不是 60×20 时，由 Layout Engine 选择降级布局；不得把内容写出终端边界。
  Pi 3 B+ 实机当前尺寸精确为 60×20（详见第 4 节 R012 与 IMPL-001 第 2.2 节），因此
  任何与 60×20 不一致的渲染都属于回归。

列宽参考：

```text
0         1         2         3         4         5
123456789012345678901234567890123456789012345678901234567890
```

### 4.1 信息层级

1. 顶栏：产品、唯一 node 别名、页面、连接状态、本地时间。
2. Coding Plans：Codex、MiniMax、Kimi Code、Grok，固定按用户配置顺序展示。Grok 当前只有 weekly 窗口时仍使用两行卡片：第一行显示 weekly 剩余量和重置时间，第二行显示 `5H --` 占位符和状态，不把占位符当作 5 小时数据。
3. API Balance：DeepSeek API、Kimi API；余额不得伪装成 Token 剩余百分比。

2026-10-07 Kimi 月额度扩展：有月数据时，进度条紧下一行显示 `MONTH USED: TOTAL 90.5% | CODE 90.3%`，数值为已用比例并保留一位小数；仅显示上游提供的月总额度/月编程额度。下一行继续显示 5H/WEEK 余量及统一状态。无月数据保持两行卡片；AUTH 不显示缓存月数值。四张 Coding 卡片加一个月详情行仍须满足 60×20 ASCII/Rich 网格，后续卡片和 API 区样式按实际行数定位。
4. Pi 状态：温度、CPU、内存、LAN。
5. 页脚：告警数量、同步新鲜度、数据来源、Kiosk 状态和版本。

### 4.2 进度条规则

- 固定 16 格，按剩余百分比四舍五入到最近格。
- rich 模式中括号和 `█` 使用亮青色，`░` 使用亮黄色；让剩余与已消耗快速分区，同时避免把整条进度误读为告警状态。
- 上游没有 limit 时不显示进度条，改用 `VALUE --` 或金额主值。
- `estimated`/`manual` 值在主值后追加 `EST`，不能显示为精确 `OK`。
- 剩余值和使用值不得在同一行混用；默认统一显示 `LEFT`。

OpenCode Go 扩展：主进度条与 RESET 对应 5 小时窗口，下一行显示 `5H 80% | WEEK 65% | MONTH 50% LEFT`，同一行全部使用剩余语义。月额度参与状态且不替代主进度条。Coding 区超过 10 行卡片容量时按完整卡片轮换子页，标题显示 `CODING PLANS 1/2` 等页码；默认 15 秒，随 CODING dwell 配置变化，CRIT 期间仍轮换。每张卡片的数值与状态必须在同一子页完整出现。

### 4.3 时间格式的两种取整

- 「距今多久」向下取整：观察于 119 秒前显示 `1M AGO`，不显示 `2M AGO`，避免高估陈旧度。
- 「还有多久重置」四舍五入到最近单位：距重置 1 小时 59 分显示 `RESET 2H`。
  若同样向下取整，整个窗口内几乎都会显示 `RESET 1H`，持续低估等待时间。

+----------------------------------------------------------+

页面顺序：`CODING`、`API`、`HOMELAB`、`SERVICES`、`SYSTEM`。自动轮播只在 Phase 3 启用。

Phase 3 页脚固定显示 `PAGE n/5`、当前页停留时间和 `SOURCE`；不显示按键、触摸或本地导航提示。
启动先显示 `CODING`。`CRIT` 不抢占或暂停五页轮播；按配置继续切页，保留严重状态文字、颜色与告警计数。

`API` 页面只显示 API 余额/成本卡；`SERVICES` 页面显示最多 5 个服务行和一行容器/环境摘要；
`SYSTEM` 页面显示 Pi 温度/CPU/内存、同步状态、版本和最多 4 个连接器健康。无数据使用 `N/A`，
连接器网络失败使用 `STALE/ERROR`，认证失败使用 `AUTH`，不得用空值伪装为 0 或 DOWN。

`HOMELAB` 每个子页最多 4 个节点，`SERVICES` 每个子页最多 5 项；超出容量时按当前页面的
dwell 周期轮换，并在标题显示 `n/m` 子页号。CRIT 卡片稳定排在正常卡片之前并固定首屏；
告警解除后恢复配置顺序和正常子页轮换。

### 6.1 CODING 页三行卡片（2026-10-10 改版）

轮播的 `CODING` 页每个子页固定两张三行卡片，卡片之间用分隔线隔开。本节样图与实现输出
逐字节一致（ASCII 模式）：

```text
| CODING PLANS                                   1 WARN    |
| ------------------------------------------------------   |
| Codex            42% LEFT                        OK      |
| [##############--------------------]       RESET 2H14M   |
| 5H 42% | WK 67% | MO --                                  |
| ------------------------------------------------------   |
| Kimi Code        15% LEFT                      WARN      |
| [#####-----------------------------] EST   RESET 4H02M   |
| 5H 15% | WK 51% | MO 60% | USED TOT 90.5% CODE 25.0%     |
| ------------------------------------------------------   |
```

- 名行：Provider 名（最多 16 字符）、主窗口剩余百分比、右侧状态徽标。
- 进度条通栏 34 格；rich 模式按剩余量着色（>50% 绿、20~50% 黄、<20% 红），已消耗 `░`
  仍为亮黄，`EST` 为黄色，`RESET` 为青色，分隔线重绘为暗灰 `─`。
- 重置倒计时在一天内精确到分钟（`RESET 2H14M`），超过一天仍按天显示（`RESET 3D`）；
  滚动窗口无准确时间时显示 `ROLLING`。
- 详情行汇总 `5H`/`WK`/`MO` 三个窗口，未知窗口显示 `--`；有月用量数据时追加
  `USED TOT .. CODE ..`（已用比例，一位小数）。
- weekly-only 卡片同样为三行：详情行 `5H --` 为占位符，`WK` 位显示 weekly 余量。
- `AUTH` 卡片名行显示 `-- LEFT` 与 `AUTH` 徽标，第二行为 `ACTION:` 指引，第三行留空；
  不得显示缓存的旧数值。

### 6.2 紧凑总览候选（2026-10-10，离线验证）

第一轮仅验证候选，未替换 6.1 的正式 CODING 页；正式接入规则见 6.3。通过 `homepi-display preview` 重放本地
脱敏快照；不连接 daemon、不写 TTY、不修改 DietPi 服务。沿用实机 480×320、Fixed 8×16、
60×20 字符网格，不缩小字体。

- 外框保留顶/底线、标题栏下方及设备区上方分割线；顶栏 1 行、数据区 13 行、Pi 状态 1 行、同步/告警 1 行。2026-10-10 用户要求恢复标题栏分割线：第 3 行为整行分割线，rich 使用亮青 `├─…─┤`，ASCII 使用 `+---…---+`，PLAN / LEFT 表头从第 4 行开始。
- 订阅表格为 `PLAN / LEFT`、`5H`、`WEEK`、`MONTH`、`RESET`、`STATUS`；每个订阅 1 行。
  名称最多 16 字符，超长用 `~` 标示；取消重复 LEFT 标签与大进度条。
- 窗口值统一为剩余额度；weekly-only 的 5H 为 `--`，WEEK 显示实际周余量，不能复制到 5H。
- 2026-10-10 单行统一：Kimi 与其他订阅一样只占一条额度行，总览不追加 `MONTH USED` 行。月总额度和月编程额度的已用明细保留在原详情布局，继续区分 TOTAL/CODE。
- FIX-007：Kimi `MONTH` 为月总额度剩余（如 7.73% 按既有规则显示 8%）；没有 TOTAL 时保持 `--`，不使用 CODE 替代。Codex 窗口按上游时长进入实际列；当前只提供 weekly 时显示 `5H -- / WEEK 54% / MONTH --`。独立 Codex Review 不得覆盖主订阅 WEEK。
- API 主余额逐项 1 行，保留币种和两位小数；不同币种与余额不能压缩成百分比。
- 2026-10-10 显示微调：最后一条订阅或 ACTION 行与 `API BALANCE` 标题之间固定保留一个空行，空行计入 13 行数据容量；超容量继续明确回退，不能为保留空行而隐藏主值。
- 紧凑 rich 主题中的 5H/WEEK/MONTH 各百分比按自身显示余量区间着色，沿用详情页配色：>50% 亮绿、20%～50% 亮黄、<20% 亮红；未知 `--` 为灰色。状态徽标仍按状态规则独立着色，不把整张卡片的最严重状态套到所有窗口。
- AUTH 隐藏全部窗口和金额，保留状态与独立 ACTION 行；STALE 保留值并显式标记。原详情页的月已用、AUTH 隐藏及月额度告警语义保留。
- 估算值始终标记 EST；未知值使用 `--`。状态不只依赖颜色；rich 与 ASCII 内容和网格一致。
- 数据区超出 13 行或主值无法完整放入时返回明确错误，不静默隐藏实体或截断主值。
- 预览默认按离线快照计算新鲜度；`--connected` 只用于显式重放采集时的在线场景。
  本地预览不采集 Pi health，因此设备指标显示未知；HomeLab/Services 仍属独立详情页。

## 7. Phase 4：远程显示覆盖

远程消息替换数据区顶部三行，并保留来源、严重度和自动恢复倒计时；沿用页面外框，不再嵌套边框：

```text
| REMOTE NOTICE                 HIGH     14:40             |
| HOMELAB MAINTENANCE STARTS IN 10 MINUTES                 |
| SOURCE DEV-MAC                RETURN IN 25S              |
```

消息文本只接受 7-bit 可打印字符并截断到可见区域；控制字符、ANSI、Markdown、URL 或命令均不解析。
CRIT 不抢占远程消息；消息到期后恢复其下方仍有效的远程页面覆盖或此前自动轮播位置。

## 8. 状态与颜色映射

| 文本 | 可选颜色 | 含义 |
|---|---|---|
| `OK` / `LIVE` | 亮绿色 | 当前值有效且在新鲜度窗口内 |
| `WARN` | 亮黄色 | 配额、余额或资源接近阈值 |
| `CRIT` / `DOWN` / `ERROR` | 亮红色 | 严重阈值、目标离线或采集错误 |
| `STALE` / `OFFLINE` | 黄色 | 显示的是最近成功值 |
| `AUTH` | 亮洋红 | 官方 CLI 登录态需用户在远端续期 |
| `N/A` | 白色 | 上游不支持或兼容接口不可用 |
| `WAIT` / `DELAY` | 亮青色 | 等待第一份快照或按设计延迟 |

## 9. 文本与数值格式

- 时间：`14:32`；距今：`38S AGO`、`12M AGO`、`2H AGO`。
- 重置：`RESET 2H`；滚动恢复但无准确时间：`ROLLING`；轮播 `CODING` 页使用分钟精度变体 `RESET 2H14M`（见 6.1）。
- 金额：`CNY 49.58` 或 `USD 12.30`，币种永不省略，固定两位小数（补零或 half away from zero 四舍五入）。
- 百分比：整数显示；低于 1% 时显示 `<1%`，未知显示 `--`。
- 温度：`52C`；CPU/内存/磁盘为整数百分比。
- Node 别名推荐不超过 12 字符；Provider 显示名推荐不超过 12 字符。
- 所有用户可配置文本必须清除控制字符和不可打印字符。

## 10. 重绘策略

- 数据变化时只更新状态模型，由终端渲染器输出一帧完整的确定性画面。
- 无数据变化时仅在分钟变化、新鲜度等级变化或轮播切页时重绘。
- 不使用 spinner、进度动画或闪烁光标。
- 光标隐藏；应用退出或崩溃时由恢复逻辑还原终端状态。
