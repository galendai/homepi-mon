# 修复记录 001：分支审查问题整改

> 日期：2026-08-10
> 状态：完成，待用户检查
> 范围：Phase 1 P1-01 ~ P1-03 审查问题

## 1. 目标

修复本分支审查发现的全部问题：

1. 将真实连接器失败传播到已有指标与 TUI 卡片状态。
2. 防止新 daemon 的空快照覆盖 Pi 最近成功快照。
3. 保证 `Retry-After` 是不可突破的最小等待时间。
4. 将必需的 `.vibe` 规格与测试文档纳入版本控制。
5. 在健康连接后重置 display 同步客户端的重连退避。
6. 完整维护连接器最后成功时间、连续失败次数和下次尝试时间。
7. 在原子替换快照后同步父目录，补齐断电持久性保证。

## 2. 验收标准

- 真实连接器先成功、再返回认证或网络错误时，旧值保留，但卡片立即进入 `AUTH` 或 `STALE`。
- daemon 新 epoch 在首次成功采集前不得覆盖已有最近成功快照。
- 任意抖动值下，429 的下一次请求都不早于 `Retry-After`。
- 健康会话后的下一次断线从首次重连退避开始。
- 连续失败健康记录保留最后成功时间，准确记录失败次数与下次尝试时间；成功后清零。
- 快照文件与父目录均完成持久化同步。
- `make check`、`go test -race ./...` 和完整交叉构建矩阵通过。
- 必需规格、实现与测试文档不再被 `.gitignore` 排除。

## 3. 执行顺序

1. 订正 HL-Spec、Module Spec、测试文档和实现说明。
2. 添加失败场景回归测试。
3. 最小化修改状态、调度、同步、事件流和快照存储实现。
4. 执行全量验证并回填实际结果。

## 4. 实际结果

- Current State 新增 connector 与 metric ID 的内存归属，真实采集失败会标记旧指标，成功恢复会清除错误。
- Scheduler 统一维护最后成功、连续失败和下次尝试时间；`Retry-After` 成为硬下限。
- 空 daemon 的 WebSocket stream 只发 heartbeat，首次真实指标到达后才发完整快照。
- Sync Client 仅在收到有效快照后将缓存数据标记为 LIVE；有效快照或心跳会重置历史重连失败计数。
- Snapshot Store 在文件 fsync 与 rename 后同步父目录；非 Unix 目标保留显式兼容实现。
- `.vibe/` 已从 `.gitignore` 移除，规格、测试和实施文档进入待提交范围。
